# Agent 上下文压缩

## 核心结论

长任务的上下文会被消息和工具结果逐渐填满。教程优先保存、裁剪可恢复的工具输出，最后才用模型总结历史；处理时须保留当前请求，并避免拆散工具调用与对应结果。

## 解释与适用条件

示例依次处理单轮过大的工具结果、过长的消息历史、较早且已被模型读过的工具结果；仍超限才保存完整记录并生成摘要。完整输出和历史被写入文件，缩短后的消息保留恢复路径。字符数只是 token 需求的估计，因此 API 真正报上下文超限时还设有一次应急压缩。模型主动请求压缩时，应先完成同批全部工具调用并回传结果，再改写历史，避免遗漏副作用或留下孤立的工具结果。
