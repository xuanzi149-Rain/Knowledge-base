# Agent 定时调度

## 核心结论

定时调度保存执行时间和任务提示，在时间到达时先入队，待 Agent 空闲再开启新一轮工作。它调度的是未来的 Agent 请求，不是已启动后台命令的完成结果。

## 解释与适用条件

教程使用五字段 cron 表达式，创建时校验格式和值域。调度线程按本地时间检查到期任务，以 `last_fired` 避免同一分钟重复入队，以 `pending_delivery` 记录尚未交付的任务。队列处理器取得 Agent 锁后才启动定时轮次，避免与用户轮次同时改写会话。

`durable=True` 保存任务定义并在进程重启后加载；非持久任务只保存在内存。任务定义持久化不代表 Agent 关闭时仍会执行，也不会补跑停机期间错过的时间。交付语义至少一次：若模型接受请求后、确认状态落盘前进程退出，重启后可能再次交付。因此实际任务应考虑重复执行。后台线程中的交互式权限请求无法读取主终端输入，教程会拒绝这类操作。
