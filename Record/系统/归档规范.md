# 归档规范

## 范围与入口

知识库根目录：`/Users/wangzixuan/Desktop/How to use Agent/Learn/Record`。

“记录学习：”“沉淀知识：”“同时归档：”统一表示提取主题知识并生成预览。显式调用 `$recording-second-brain` 也可启动此流程。没有记录请求时不主动归档。

用户指定范围时遵照该范围；未指定时使用当前可见对话的学习内容。不自行检索其他任务或聊天，不假装能读取被截断的历史。若没有足够的知识内容，说明缺少的材料，不创建空笔记。只有范围存在实质歧义时才追问。

## 知识提取

- 记录原理、方法、适用条件、实践经验与理解上的纠正。将项目特例概括为可复用知识，同时保留必要条件。
- 使用清楚、简洁的中文；技术术语、代码与必要原文可以保留。优先说明“是什么、什么时候适用、如何使用”。
- 不把任务流水账、临时进度、整段聊天或未经支持的推测当作知识结论。
- 对话中的说法不自动等于已验证事实。必要时标注“待核实”及待核实点；归档本身不意味着完成外部事实核查。
- 来源优先记录用户提供或确实查阅过的网页、文档、项目及路径；没有可引用来源时写“当前对话（日期；主题）”。不编造链接、页码、对话 ID 或出处。
- 密码、令牌、私钥、身份证件号等不进入预览、笔记和去重输出；替换为无敏感值的说明。其他私人细节只保留知识所必需的部分，优先去标识化。

## 分类、命名与链接

- `知识/` 存放独立主题笔记；`分类/` 存放分类索引。类别按实际内容创建，优先复用已有类别，不预建空类别。
- 先查现有主题是否可以容纳新增内容。主题过宽且包含独立概念时可在预览中提出拆分，但不擅自拆改已有笔记。
- 同一主题只保留一份正文，可以归属多个类别；相应分类索引均链接到它。
- 文件名使用简明主题名，避免路径分隔符以及 `[]#|^` 等影响链接的字符。同名不同义用领域限定词区分。别名记录常见称呼或缩写，不堆叠关键词。
- 内部链接使用相对知识库根目录的完整路径，不带 `.md`，例如 `[[知识/Python 可变对象|Python 可变对象]]`。例子是格式说明，不要求创建该笔记。
- 只链接已存在文件或同一次确认将创建的文件；链接表达具体关系，不为了数量添加链接。若主题 A 与 B 需要互链，对 B 的修改也必须进入预览。
- 新建分类时同时更新 `首页.md` 的分类导航。分类索引至少包含一级标题、一句范围说明、主题链接及简短说明，并提供 `[[首页]]` 返回入口。

## 主题格式

采用 [[模板/主题笔记模板|主题笔记模板]]。YAML 属性固定为：

- `类别`：字符串列表，每项为带引号的分类索引链接。
- `aliases`：字符串列表，无别名时为 `[]`。
- `创建日期`、`更新日期`：带引号的 `YYYY-MM-DD` 日期，按用户当地日期；创建日期保持不变，实际内容变化时修改 `更新日期`。

正文按需要保留“核心结论、解释与适用条件、例子或操作步骤、来源、相关知识”。核心结论与来源必需，其余空章节删除。不添加复习日期、自测题或学习日志。

## 检索与合并

1. 列出分类与知识文件，检索标题、别名、关键词、同义说法、来源和核心结论，再读取可能匹配的完整笔记。不能仅凭文件名判断重复。
2. 同主题新增有效信息：在对应章节整合，保留已有有效内容、来源与创建日期，不机械地追加一份重复总结。
3. 只有措辞不同、结论相同：报告重复，不写文件、不变更更新日期。新来源具有补充价值时可单独预览来源更新。
4. 不同主题但有关联：新建或更新各自笔记，通过必要链接关联。
5. 新旧结论冲突：预览明确列出旧说法、新说法和依据。上下文或适用条件不同则写清边界；无法判断则保留分歧与待核实标记，或询问用户，不静默覆盖。

## 预览与确认

预览只保留在当前对话，不向知识库写入预览文件或状态文件。每次预览使用唯一编号，例如 `SB-20261001-153000-a7f2`（时间加随机后缀）。同一对话仅保留一个有效预览；修改、取消或新归档请求使前一个失效。

每份预览包含：

1. **编号与范围**：本次来源范围、知识摘要及尚未核实的内容。
2. **检索结果**：匹配到哪些笔记，分别选择合并、新建、互链或跳过的理由；说明检索是否完整。
3. **文件清单与基线**：每个目标的绝对路径、操作类型；已有文件记录内容 SHA-256，新文件记录“不存在”。包括首页、分类和相关笔记的变更，不能只列主题正文。预览所依赖的规则与模板也记录 SHA-256，包括 `AGENTS.md`、`系统/归档规范.md`，以及本次使用的 `模板/主题笔记模板.md`；下文“规范基线”均指这组实际依赖文件。
4. **完整变更**：新文件展示全文；已有文件展示准确 diff 或修改后全文，足以确认最终内容。若删除、重命名或拆分有必要，单独列明影响，不混入普通更新。
5. **链接及省略项**：新增关系、冲突处理方式，以及敏感内容已省略的概括，不重复敏感原值。
6. **确认指令**：`确认归档 <编号>`；用户可提出修改或取消。

全为重复内容时无需生成空的写入预览，直接说明没有变更。

只对当前对话中可恢复完整内容、编号和基线的有效预览接受确认。收到不带编号的“确认”时请用户引用当前编号；旧编号、取消后的编号或无法恢复的预览均不得用于写入，应重新预览。

## 确认后的写入与核对

1. 收到对应确认后，先核对全部目标文件及规范的当前 SHA-256 与基线；新文件仍须不存在。任一变化则停止本次写入，读取最新状态并生成新预览。权限受限时保留完整预览，说明未写入的路径，不另选库目录。
2. 严格应用确认过的内容，不在确认后继续润色或追加知识。先写主题文件，再写分类、关联笔记和首页；新建文件不得覆盖同名文件。
3. 逐个重读并与预览核对，检查 YAML 属性、链接目标和分类导航。写入时间与预览日期跨日时也不要悄悄修改已确认内容。
4. 返回“已创建／已更新／未完成”的准确清单与可点击绝对路径链接。部分失败时停止后续写入，列出已完成和未完成项，不声称全部成功；基于实际状态重新生成剩余变更预览。

该流程由 Agent 执行，不提供数据库事务或多进程锁。请避免在确认写入期间同时编辑目标文件；发现并发变化时重新预览，不尝试盲目覆盖。

## 无文件访问能力时

使用 [[系统/通用记录提示词|通用记录提示词]]。请用户提供本规范、分类索引及可能相关的主题笔记后，才能判断对应内容如何合并。只有局部材料时明确检索范围，不能声称已完成全库去重。

没有现有库内容时，可以先给“待归档草稿”；不能断言主题不存在。不能计算真实文件基线时标注“未读取文件，待本地核对”。用户确认后提供最终文件内容和建议路径供手动保存，明确未实际写入；也可交给具备本地访问能力的 Codex 重新检索、预览并确认。
